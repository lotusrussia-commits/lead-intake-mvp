# Lead Intake MVP

Мини-сервис для автоматического приема заявок.

Проект решает проблему потери заявок: данные приходят через HTTP endpoint, проходят валидацию, сохраняются в SQLite и фиксируются в журнале событий.

## Возможности

- Прием заявок через API endpoint `POST /lead`
- Валидация входных данных
- Сохранение заявок в SQLite
- Автоматическое создание таблицы `leads`
- Логирование успешных заявок
- Обработка ошибок:
  - некорректные данные → HTTP 400
  - ошибка базы данных → HTTP 500 + запись в лог


## Технологии

- Python 3.12
- FastAPI
- SQLAlchemy
- SQLite
- Pydantic
- Uvicorn

## Установка

Клонировать репозиторий:

```bash
git clone <ссылка-на-GitHub>
```

Перейти в папку проекта:

```bash
cd lead-intake-mvp
```

Создать виртуальное окружение:

python3 -m venv venv

Активировать виртуальное окружение:

```bash
source venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```
## Запуск проекта

Запустить сервер FastAPI:

```bash
uvicorn app.main:app --reload
```

После запуска открыть в браузере:

http://127.0.0.1:8000/docs

Откроется Swagger UI для тестирования API.

Использование API

Endpoint:

POST /lead

Пример запроса:

```json
{
  "name": "Ирина",
  "contact": "+79990000000",
  "source": "landing",
  "comment": "Хочу консультацию по тарифам"
}
```

Успешный ответ:

```json
{
  "status": "success",
  "message": "Заявка сохранена",
  "id": 1
}
```

## Проверка результата

После отправки заявки данные сохраняются в SQLite и фиксируются в журнале событий.

База данных

Используется SQLite.

Файл базы данных:

leads.db

Таблица:

leads

Поля таблицы:

id
created_at
name
contact
source
comment
Журнал событий

Успешные заявки записываются в файл:

events.log

Пример записи:

2026-07-28 22:59:51 - New lead saved: 1
Проверка обработки ошибок

Если отсутствует обязательное поле contact:

Пример запроса:

{
  "name": "Петр",
  "source": "site",
  "comment": "Нет телефона"
}

Ответ сервера:

HTTP 400 Bad Request

Пример ответа:

{
  "error": "Некорректные данные заявки"
}
Архитектура проекта

Логика работы сервиса:

HTTP POST /lead
        |
        ↓
Валидация данных (Pydantic)
        |
        ↓
Сохранение заявки в SQLite
        |
        ↓
Запись события в events.log
        |
        ↓
Ответ клиенту
